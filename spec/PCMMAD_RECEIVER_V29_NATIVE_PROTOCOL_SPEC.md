# PCMMAD Receiver V29 Native Protocol Release Candidate Spec

## Objective

Promote the verified V28 receiver into a cohesive PCMMAD-native lab protocol without losing routes, server-native capabilities, or Custom GPT compatibility.

## Preservation contract

- at least 49 Flask routes
- all 75 V28 server-native tools retained
- 30 unique Custom GPT operations retained
- authentication, project, context, execution, research, archive, filesystem, browser, Git, SOP, CSC, doctrine, semantic, state, session, approval, result-handle, and mount capabilities retained
- surviving V28 regression tests remain green

## V29 additions

- 12 PCMMAD-native protocol tools behind `/lab/dispatch`
- typed runtime modes and proportionate rigor levels
- typed objective, constraint, continuity, claim, evidence, artifact, adjudication, and waiver records
- append-only JSONL protocol ledger with sequence and hash-chain verification
- rebuildable derived state projection
- explicit discourse/build/promotion mode guard
- compatible `off`, `advisory`, and `strict` dispatch enforcement
- freshness-aware evidence with verifier identity, status, observed time, expiry, digest, and distinctness
- scoped, owned, expiring waiver lineage
- sealed artifact identity protection
- promotion evidence thresholds by rigor level

## Boundary

PCMMAD Receiver is the product. Forge and CTO/CSC source packages are evidence and doctrine inputs. No source-project namespace becomes part of PCMMAD's executable public identity.

## Required gates

1. source inventory and cross-reference audit
2. Python compilation
3. complete regression suite
4. boot self-test
5. route trace
6. schema authority and 30-operation uniqueness
7. server-native tool preservation plus protocol-family presence
8. protocol ledger, tamper, rigor, evidence freshness, seal, waiver, and mode-gate tests
9. negative contract, replay, concurrency, security, browser resilience, live parity, launcher, and package-integrity gates
10. CSC doctrine availability, freshness, holonic, coverage, and PDVER finalization
11. clean final ZIP extraction and manifest verification

## Host-bound gates

- Windows PowerShell execution
- Python 3.12 virtual-environment installation on the target machine
- live D:/E: mount verification
- ngrok tunnel and real Custom GPT callback

These are explicit deployment gates, not claims made from the sandbox.

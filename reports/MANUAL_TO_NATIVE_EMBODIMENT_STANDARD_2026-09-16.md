# MANUAL / SEMANTIC -> NATIVE EMBODIMENT STANDARD

## Governing law
**REPEATED MANUAL/SEMANTIC WORK != ACCEPTABLE STEADY STATE.**

Any operation repeated by a model/operator, or any one-off operation whose incorrect execution has material consequence, is an architectural embodiment candidate. Preferred destination: authoritative native transaction, sealed workflow/plan, durable automation, or bounded recovery program. Chat/manual choreography is bootstrap/recovery only.

## AI weakness threat model
- context loss / stale state -> durable currentness witnesses, checkpoints, bounded rehydration
- fluent false completion -> mandatory consequence receipts/readback
- stale tool shape -> adaptive ingress and server-corrective contracts
- long-horizon procedural drift -> sealed workflows with assertions/stop conditions
- local-green bias -> whole-system hostile engineering / interaction qualification
- approval retry mistakes -> exact continuation-aware resubmission
- hidden environment assumptions -> explicit environment/currentness witnesses
- repeated semantic synthesis -> server-side loop with durable evidence lineage
- authority confusion -> argument/authority separation + generation fences
- recovery improvisation -> tested recovery programs + convergence gates

## Admission rule
Embody authoritative semantics once, then expose adapters. New machinery must reduce semantic degrees of freedom, preserve lineage, define authority/idempotency, and make exact completion evidence unavoidable.

## Anti-patterns
- wrapping manual shell without authoritative semantics
- duplicating transactions across routes/tools
- equating submitted/started with complete
- mutation hidden behind read/plan labels
- chat memory used as workflow state
- weakening gates to make automation green


# PCMMAD Receiver V28 PDVER Recovery Refactor Spec

## Purpose

Promote the surviving receiver into a coherent, reproducible Windows deployment without losing route, tool, schema, continuity, execution, research, archive, browser, Git, doctrine, SOP, or state capabilities.

## Architectural form

- thin process entrypoint
- explicit application factory
- required/optional blueprint policy
- stable direct route families
- server-native capability registry and router
- typed machine/runtime configuration
- mount-governed storage
- sidecar-separated browser capability
- compact 30-operation Custom GPT schema
- evidence-bearing release gates

## Required evaluation gates

The release contract in `docs/verification/RELEASE_CONTRACT.md` is normative. All generated reports and the final package manifest are sidecar evidence; they do not contaminate executable source semantics.

## Feature-preservation numbers

- runtime route count: 49
- registered server tool count: 75
- Custom GPT operation count: 30

Any future pass changing these numbers must identify the intentional addition/removal and update route/tool/schema authority evidence in the same promotion.
